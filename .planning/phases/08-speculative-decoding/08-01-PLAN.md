<objective>
Implement speculative decoding to achieve 1.5-2.8x throughput increase using a smaller draft model to predict tokens ahead, verified by the target model.

Purpose: This is the highest-impact performance optimization for local inference. By using a smaller, faster draft model to predict N tokens ahead and then verifying them with the full target model in parallel, we can dramatically reduce per-token latency without any quality degradation.

Output: Working speculative decoding system with automatic draft model selection, CLI configuration, and performance metrics.

<research>
Speculative Decoding Algorithm (from "Fast Inference from Transformers via Speculative Decoding", arXiv:2211.17192):

**Core Algorithm:**
1. Use a small, fast "draft" model to generate K tokens autoregressively
2. Run the large "target" model once on the K draft tokens in parallel
3. Compare target model probabilities with draft model probabilities
4. Accept draft tokens with probability: min(1, p_target(x) / p_draft(x))
5. Reject tokens that fail - restart from last accepted position
6. Continue until completion

**Key Implementation Details:**
- Acceptance probability: For each token position i, accept with probability min(1, p_target(i) / p_draft(i))
- On rejection at position j: Target model provides new token at j, then restart speculation
- Expected acceptance rate: Typically 0.6-0.8 for well-matched draft/target pairs
- Speedup formula: ~ K / (1 + αK) where K is speculation depth, α is rejection rate
- With K=4 and 70% acceptance: ~2.8x speedup; with K=4 and 50% acceptance: ~1.6x speedup

**Draft Model Selection Strategy:**
- Same architecture family (Qwen drafts for Qwen targets)
- Typically 1/4 to 1/8 the size (1.5B draft for 7B target)
- Common patterns: Qwen2.5-Coder-1.5B as draft for Qwen2.5-Coder-7B
- Automatic detection by model name pattern matching
- User can override with explicit --draft-model flag

**Performance Requirements:**
- Draft model must be significantly faster than target (at least 4x)
- Target model forward pass on K tokens should be ~1.1x cost of single token (due to parallelization)
- Memory overhead: Draft model weights (manageable for 1.5B models: ~3GB)

**Integration Points:**
- GenerationState.next() becomes the delegation point
- When draft available: use SpeculativeGenerator
- When draft unavailable: fall back to standard GenerationState
- Must maintain exact same output distribution (verified by algorithm)

    **Algorithm Implementation:**
    1. `next()` method implements the full speculative loop:
       - Generate K draft tokens autoregressively using draft model
       - Run target model once on [context + draft_tokens] to get parallel logits
       - For each position i (0 to K-1):
         * Compute acceptance probability: min(1.0, p_target[i] / p_draft[i])
         * Sample from uniform distribution to decide acceptance
         * If accepted: emit token, continue to next position
         * If rejected: use target distribution for this position, stop speculation
    
    2. **Probability Computation:**
       - Get probability distribution from logits using softmax
       - Extract probability for the draft token at each position
       - Compute acceptance ratio with numerical stability
    
    3. **State Management:**
       - Maintain both target and draft KV caches
       - On rejection: reset caches to position before failure
       - On acceptance: advance both caches by accepted tokens
    
    4. **Edge Cases:**
       - EOS handling: stop speculation early if draft produces EOS
       - Stop sequences: check on accepted tokens
       - Max tokens: respect generation limit
       - Temperature 0: greedy selection in both models
    
    **Integration with Existing System:**
    - Implement same interface as GenerationState for drop-in replacement
    - Support all GenerationOptions (temperature, top_p, penalties, etc.)
    - Delegate option application to draft and target appropriately
    - Maintain GenerationResult compatibility for streaming
    
    **Files to Create:**

    - src/speculation/speculative_generator_test.zig (TDD test file)
    
    **Key Decisions (from RESEARCH):**
    - Speculation depth K=4 (configurable, optimal for most cases)
    - Acceptance uses exact probability ratio (not approximation)
    - Both caches maintained simultaneously (memory tradeoff for speed)

        // ... existing fields ...
        
        // Speculative generation delegation
        speculative_generator: ?*speculation.SpeculativeGenerator = null,
        use_speculation: bool = false,
        
        pub fn init(
            allocator: std.mem.Allocator,
            transformer: *qwen.Transformer,
            initial_tokens: []const u32,
            eos_token_ids: []const u32,
            options: GenerationOptions,
            tokenizer: ?*mlx_tokenizer.Tokenizer,
            draft_model: ?*DraftModel,  // NEW: optional draft model
            speculation_depth: usize,     // NEW: config
        ) !Self {
            // If draft available and speculation enabled, create SpeculativeGenerator
            if (draft_model != null and speculation_depth > 0) {
                const spec_gen = try allocator.create(speculation.SpeculativeGenerator);
                spec_gen.* = try speculation.SpeculativeGenerator.init(
                    allocator,
                    transformer,
                    draft_model.?,
                    speculation_depth,
                    options,
                );
                return Self{
                    // ... standard fields ...
                    .speculative_generator = spec_gen,
                    .use_speculation = true,
                };
            }
            
            // Otherwise, standard initialization
            return standardInit(...);
        }
        
        pub fn next(self: *Self) !?Token {
            if (self.use_speculation and self.speculative_generator != null) {
                return try self.speculative_generator.?.next();
            }
            return try self.standardNext();
        }
        
        pub fn deinit(self: *Self) void {
            if (self.speculative_generator) |sg| {
                sg.deinit();
                self.allocator.destroy(sg);
            }
            // ... rest of cleanup ...
        }
    };

    # Speculative Decoding in zlx
    
    ## Overview
    
    Speculative decoding uses a small, fast "draft" model to predict tokens ahead,
    then verifies them with the full target model. This achieves 1.5-2.8x speedup
    with no quality degradation.
    
    ## Algorithm
    
    1. Draft model generates K tokens autoregressively (default K=4)
    2. Target model verifies all K tokens in parallel
    3. Accept tokens with probability min(1, p_target / p_draft)
    4. On rejection, use target model output and restart
    5. Continue until completion
    
    ## Usage
    
    ### Automatic Draft Selection
    
    zlx automatically selects compatible draft models:
    
    ```bash
    zlx --model Qwen2.5-Coder-7B-4bit
    # Auto-selects: Qwen2.5-Coder-1.5B-4bit (if available)
    ```
    
    ### Manual Draft Selection
    
    ```bash
    zlx --model Qwen2.5-Coder-7B-4bit \
        --draft-model Qwen2.5-Coder-0.5B-4bit \
        --speculation-depth 6
    ```
    
    ### Configuration File
    
    ```json
    {
      "speculation": {
        "enabled": true,
        "speculation_depth": 4,
        "draft_model": null  // null = auto-select
      }
    }
    ```
    
    ## Compatible Draft/Target Pairs
    
    | Target | Recommended Draft | Expected Speedup |
    |--------|-------------------|------------------|
    | Qwen 7B | Qwen 1.5B | 2.0-2.8x |
    | Qwen 7B | Qwen 0.5B | 1.8-2.5x |
    | Llama 8B | Llama 1B | 1.5-2.2x |
    
    ## Metrics
    
    View speculation metrics:
    ```bash
    curl http://localhost:8081/v1/metrics/speculative
    ```
    
    Key metrics:
    - `acceptance_rate`: Fraction of draft tokens accepted (target: >0.6)
    - `avg_tokens_per_step`: Average tokens generated per speculation
    - `estimated_speedup`: Calculated speedup based on acceptance rate

    **Low acceptance rate (< 0.4):**
