```zig
// The DeepSeekLayer stores a value, but deinit() on value calls destroy() which will crash
// See Approach B for the safer stub.
```

**Approach B — Stub value (acceptable per D-05, avoids deinit crash):**
```zig
// Stub: populate struct fields directly to match actual struct definition
```

**Decision rule:** Use Approach B. Reason: `DeepSeekLayer.mla` is a value type. `mla.MultiHeadLatentAttention.init()` returns a heap-allocated pointer, and `deinit()` calls `allocator.destroy(self)` — storing the dereferenced value and then calling deinit() on it would double-free or corrupt memory. Approach B produces a valid value that matches the field type, compiles cleanly, and does not introduce a memory bug. This is consistent with D-05 (stubs that compile are fine).
