<critical_findings>
**STACK.md Research Finding (High Confidence):**
- TurboQuant is 100% Python with no C/C++ API to bind
- Metal kernel source strings are embedded in Python via `mx.fast.metal_kernel()` (MLX Python JIT API)
- No C header, no shared library, no extern ABI to call from Zig
- `quantize_key`, `dequantize`, and Hadamard rotation kernels are Python functions that JIT-compile Metal shader source strings at runtime

**Porting Options Evaluated:**
| Option | Effort | Confidence | Notes |
|--------|--------|------------|-------|
| Port Metal kernel source strings to C++ and expose via mlx-c custom ops API | High | LOW | mlx-c v0.1.2 predates the custom ops API; would require upgrading mlx-c and implementing the C++ primitive, which breaks MLX.zig's pinned version |
| Write Zig wrappers around equivalent mlx-c array ops (Hadamard-ish, quantized matmul) | Medium | LOW | Approximation; loses kernel fusion benefit; not the same algorithm |
| Defer TurboQuant entirely from MVP | Low | HIGH | Correct scope given complexity |
| Use a Python sidecar process for TurboQuant compression, communicate via IPC | Very High | MEDIUM | Defeats the "no Python" requirement |
</critical_findings>

    ## Source Repository

    - Parallel WHT implementation with threadgroup barriers
    - v2: Parallel implementation (d threads per vector)
    - Achieves 1.3-2.3x speedup over v1

    - PolarQuant algorithm
    - Lloyd-Max codebook generation (can precompute)
    - Scalar quantization/dequantization logic
    
    ### 4. rotation.py
    - Walsh-Hadamard Transform logic
    - Random sign flipping for Gaussianization
    
    ### 5. cache.py
    - TurboQuantKVCache class (drop-in replacement for mlx-lm KVCache)
    - Layer-adaptive compression logic

    - Bind from Zig
