Note on httpz method routing: httpz zig-0.13 branch uses `Server(void)` (context=void).
Method handlers like `ToolsAPI.browserToolHandler` are instance methods and require a
closure or wrapper function that captures the ToolsAPI pointer. The cleanest approach
for Zig 0.13.0 is a module-level var for the ToolsAPI instance and thin wrapper functions,
matching the existing `handleChatCompletions` → `handlers.handleChatCompletions` pattern
already in server.zig.

  <name>Task 2: Dispatch /v1/chat/completions to ChatGPTOSSHandler for gpt-oss models</name>
  <files>src/api/server.zig</files>
  <action>
    Modify the existing `handleChatCompletions` wrapper function in `server.zig`. Currently it unconditionally calls `handlers.handleChatCompletions(req, res)`. Change it to peek at the request body and dispatch to `ChatGPTOSSHandler` when the model name starts with `"gpt-oss"`.

    The request body is JSON with a `model` field. Use a minimal struct parse to read just the model name:

    ```zig
    fn handleChatCompletions(req: *httpz.Request, res: *httpz.Response) !void {
        // Peek at model field to dispatch GPT-OSS requests to dedicated handler
        const body = req.body() orelse {
            try handlers.handleChatCompletions(req, res);
            return;
        };

        const ModelPeek = struct { model: []const u8 = "" };
        const peek = std.json.parseFromSlice(ModelPeek, req.arena, body, .{ .ignore_unknown_fields = true }) catch {
            // Parse failed — fall through to generic handler which will return proper error
            try handlers.handleChatCompletions(req, res);
            return;
        };
        defer peek.deinit();

        if (std.mem.startsWith(u8, peek.value.model, "gpt-oss")) {
            try chat_gptoss.ChatGPTOSSHandler.handle(req, res);
        } else {
            try handlers.handleChatCompletions(req, res);
        }
    }
    ```

    Note: `req.arena` is the per-request arena allocator provided by httpz zig-0.13. Use it for the temporary parse so it is freed automatically after the request.

    If `ChatGPTOSSHandler.handle` has a different signature than `handle(req, res)` — check `src/api/chat_gptoss.zig` and adapt the call to match the actual exported function name and signature exactly.

    Do not modify any other part of server.zig or any other handler.
