## Reference: openharmony-MLX Architecture

From https://github.com/arthurcolle/openharmony-mlx:

**GPT-OSS Model Specs:**
- gpt-oss-20b: 21B total params, 3.6B active per token
- gpt-oss-120b: 117B total params, 5.1B active per token
- MoE: 64 experts, top-6 routed + 2 shared
- Sliding window: 4096 window size for attention
- MXFP4: Native quantization for MoE layer weights

**Key Components to Port:**

1. **Sliding Window Attention** (vs full attention)
   - Only attends to last 4096 tokens
   - Reduces KV cache memory dramatically
   - Metal kernel for efficient windowed matmul

2. **MoE Routing** (native MLX, not llama.cpp)
   - Gate computes expert scores
   - Top-k selection per token
   - Sparse expert activation
   - Metal kernel for routing computation

3. **Yarn RoPE** (Yet another RoPE extension)
   - Extended context support
   - Different frequencies for long sequences

## Architecture for GPT-OSS

```
GPTOSSTransformer
├── Config (from config.json)
│   ├── hidden_size: 5120 (20B) or 6656 (120B)
│   ├── num_layers: 40 (20B) or 56 (120B)
│   ├── num_experts: 64
│   ├── num_shared_experts: 2
│   ├── top_k: 6
│   ├── sliding_window: 4096
│   └── rope_theta: 1000000.0 (Yarn)
│
├── Layers: []GPTOSSTransformerLayer
│   └── GPTOSSTransformerLayer
│       ├── input_norm: RMSNorm
│       ├── attention: SlidingWindowAttention
│       │   ├── q_proj, k_proj, v_proj, o_proj
│       │   ├── yarn_rope: YarnRoPE
│       │   └── sliding_window: 4096
│       ├── post_attn_norm: RMSNorm
│       └── moe: GPTOSSMoE
│           ├── gate: Linear (router)
│           ├── shared_experts: [2]MLP
│           ├── routed_experts: [64]MLP (sparse)
│           └── route_kernel: FastMetalKernel
│
├── norm: RMSNorm
└── lm_head: Linear
```
