<objective>
Replace the four inference stubs in gptoss.zig and mlx_gptoss_backend.zig with real MLX primitive ops. This plan can run in parallel with 15-07 since it touches different files.

Purpose: The GPT-OSS inference pipeline is currently entirely stubbed: forward() returns zero logits, generate() always emits token 1, tokenize() returns an empty slice, and load() passes `undefined` as the GPU stream (a guaranteed runtime crash). These stubs make the model structurally present but computationally inert. With real ops wired, the model can produce actual token output from loaded weights.

Constraint: Metal kernel dispatch via `mlx_fast_metal_kernel` requires mlx-c v0.4.x. The project is pinned to mlx-c v0.1.2. Use mlx-c v0.1.2 primitive ops instead: `mlx.matmul`, `mlx.argmax`, `mlx.take`, `mlx.item`. The existing MLX.zig generate loop in `src/mlx.zig/src/mlx.zig` lines 927-930 provides the exact pattern to follow.

Note on applyMoE: The MoE routing stub (identity/zeros) is intentionally left in place. MoE routing is architecturally complex and requires expert weight loading infrastructure. The identity pass allows real forward pass computation through attention layers — outputs will be sub-optimal quality but the pipeline is not broken.

Output: Two files modified. generate() produces real tokens. tokenize() returns a real token slice. load() does not crash on stream access.
</objective>

// Argmax over an axis

// Extract scalar from single-element array
pub fn item(dest: anytype, arr: Array) MLXError!void;
// dest must be a pointer: var tok: u32 = 0; try mlx.item(&tok, arr);
