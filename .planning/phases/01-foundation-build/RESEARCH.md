## Critical Finding: Zig 0.15.2, Not 0.13.0

The installed Zig is **0.15.2** (`/opt/homebrew/Cellar/zig/0.15.2_1/bin/zig`).
The CLAUDE.md tech stack table assumed 0.13.0. All version-lock decisions must be updated.

Evidence: `zig version` → `0.15.2`. The existing `src/main.zig` (generated by `zig init`) uses `std.fs.File.stdout()` — a 0.14+ API, confirming 0.15 is the active toolchain.

**Decision: Build for Zig 0.15.2, not 0.13.0.**
- MLX.zig is on `heads/main` (commit bfdb46f). We will patch the submodule's build.zig.zon locally (not committed upstream) so Zig 0.15 can parse it.
- httpz master branch targets Zig 0.15.1+ — use master, not zig-0.13.

## build.zig.zon Format Change in Zig 0.15

In Zig 0.15, the `.name` field must be an **enum literal** (identifier), not a string:
```zig
// 0.13 style (BROKEN in 0.15):
.name = "zlx",

// 0.15 style (CORRECT):
.name = .zlx,
```

Also new required/optional fields in 0.15:
- `.fingerprint = 0x...` — globally unique package ID, generated once
- `.minimum_zig_version = "0.15.2"` — optional but good practice

**Current `build.zig.zon` error:** `error: expected enum literal` at `.name = "zlx"`.

**MLX.zig submodule has same problem:** `.name = "mlx.zig"` is a string with a dot — doubly invalid. Must patch locally.

## MLX.zig Linkage Strategy (BUILD-02)

MLX.zig does NOT export a Zig module. Calling `b.dependency("mlx", .{}).module("mlx")` panics at build time. This is confirmed in CLAUDE.md and SUMMARY.md.

**Chosen approach (Approach B — inline replication):**

Do NOT include MLX.zig as a `build.zig.zon` package dependency. Instead:
1. Add **pcre2** to our own `build.zig.zon` (needed for `configureExecutable`)
2. Replicate `setupDependencies` and `configureExecutable` from `src/mlx.zig/build.zig` inline in our `build.zig`
3. Reference MLX.zig source files directly via `b.path("src/mlx.zig/src/...")`

This avoids MLX.zig's broken-for-0.15 `build.zig.zon` from blocking our build, and avoids the nonexistent module export.

## b.cache_root API in Zig 0.15.2

Verified from `/opt/homebrew/Cellar/zig/0.15.2_1/lib/zig/std/Build.zig`:
- `b.cache_root` field still exists (line 59: `cache_root: Cache.Directory`)
- `b.cache_root.path` is still `?[]const u8`
- `b.cache_root.path.?` still compiles — no change needed in `setupDependencies` for this field

`b.pathJoin` is still available. `b.addSystemCommand` is still available. The `configureExecutable` helper (using `exe.addIncludePath`, `exe.addObjectFile`, `exe.linkFramework`, `exe.linkLibCpp`) should work with minor API updates for 0.15.

## pcre2 Dependency Strategy

When we replicate `configureExecutable`, the line:
```zig
exe.linkLibrary(deps.pcre2_dep.artifact("pcre2-8"));
```
requires `b.dependency("pcre2", .{})` to resolve. This means **pcre2 must be in our `build.zig.zon`**. The hash in the new 0.15.2 format is confirmed above.
