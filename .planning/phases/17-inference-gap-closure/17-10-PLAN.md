### Task 1 — Fix deepseek_test.zig typeinfo syntax (3 errors)

**File:** `src/deepseek_test.zig`
**Errors:**
- Line 83: `@typeInfo(TestLayer).Struct.fields[0]` → `@typeInfo(TestLayer).@"struct".fields[0]`
- Line 86: `@typeInfo(TestLayer).Struct.fields[1]` → `@typeInfo(TestLayer).@"struct".fields[1]`
- Line 89: `@typeInfo(TestLayer).Struct.fields[2]` → `@typeInfo(TestLayer).@"struct".fields[2]`
- Line 92: `@typeInfo(TestLayer).Struct.fields[3]` → `@typeInfo(TestLayer).@"struct".fields[3]`
- Line 154: `@typeInfo(inference.ModelUnion).Union.fields` → `@typeInfo(inference.ModelUnion).@"union".fields`
- Line 169: `@typeInfo(TestWeights).Struct.fields[0]` → `@typeInfo(TestWeights).@"struct".fields[0]`
- Line 172: `@typeInfo(TestWeights).Struct.fields[1]` → `@typeInfo(TestWeights).@"struct".fields[1]`
- Line 175: `@typeInfo(TestWeights).Struct.fields[2]` → `@typeInfo(TestWeights).@"struct".fields[2]`

**Why:** Zig 0.15.2 renamed TypeInfo union tags from `.Struct`/`.Union` to `.@"struct"`/`.@"union"`
because these identifiers conflict with Zig keywords.

**Action:** `replace_all` `.Struct.fields` → `.@"struct".fields` and `.Union.fields` → `.@"union".fields`
in `src/deepseek_test.zig`. Only these two patterns appear — use targeted replace_all.

### Task 2 — Fix test_integration.zig const qualifier mismatch (2 errors)

### Task 4 — Add mlx.randomNormal wrapper (2 compile errors in moe.zig + moe_test.zig)

**Problem:** `mlx.randomNormal()` is called in `src/moe.zig:92` and `src/moe_test.zig:143-151` but
`src/mlx.zig/src/mlx.zig` does not export this function.

**mlx-c API available:** `mlx_random_normal(res, shape, shape_num, dtype, loc, scale, key, stream)`
— already in scope via the existing `@cImport({ @cInclude("mlx/c/mlx.h"); })` because `mlx.h`
includes `random.h`.

**Call signature used by moe.zig:**
```zig
_ = mlx.randomNormal(&gate_weight, &.{ @intCast(H), @intCast(W) }, .float32);
```
(returns void-ish result via `_ =`, no stream/key needed by callers)

**Action:** Add to `src/mlx.zig/src/mlx.zig` after the `zeros` function (around line 184).

Use the same inline comptime shape-coercion pattern already established by `arrayNewData` (line 110)
and `arraySetData` (line 124) — `utils.zig` has no `shapeToCInts` helper. Use `C.mlx_array_empty`
(a `static` in `array.h`, already in scope via `@cImport`) as the null-key sentinel.

```zig
/// Draw samples from a normal distribution N(0, 1).
/// shape: comptime-known integer tuple, e.g. &.{ rows, cols }.
/// Wraps mlx_random_normal with loc=0, scale=1, no key, default GPU stream.
pub fn randomNormal(result: *Array, shape_arg: anytype, dtype: C.mlx_dtype) MLXError!void {
    var shape: [32]c_int = undefined;
    var len: usize = 0;
    const T = @TypeOf(shape_arg);
    const fields = @typeInfo(T).@"struct".fields;
    inline for (fields, 0..) |field, idx| {
        shape[idx] = @intCast(@field(shape_arg, field.name));
        len = idx + 1;
    }
    const s = C.mlx_default_gpu_stream_new();
    defer streamFree(s);
    return mlxOp(C.mlx_random_normal(result, &shape[0], len, dtype, 0.0, 1.0, C.mlx_array_empty, s));
}
```

**Verify call sites match:**
- `src/moe.zig:92`: `_ = mlx.randomNormal(&gate_weight, &.{ @intCast(H), @intCast(W) }, .float32)` ✓
- `src/moe_test.zig:143-151`: same 3-arg pattern ✓

### Task 5 — Fix gptoss_test exit 255 (undefined stream)

**File:** `src/test_models_gptoss.zig`
**Root cause:** `testGptossInference` at line 58:
```zig
var transformer = try GPTOSSTransformer.init(allocator, config, undefined);
```
`undefined` is passed for `mlx.Stream`. When `generate()` → `forward()` calls
`mlx.zeros(..., self.stream)` and `mlx.argmax(..., self.stream)`, the uninitialized stream
pointer causes mlx-c to crash (exit 255 / SIGABRT).

**Root cause confirmed:** `gptoss_test_mod` in `build.zig` (lines 688-699) has NO `addImport` for
`mlx.zig/src/mlx.zig`, and `src/test_models_gptoss.zig` has no `const mlx = @import(...)`.

**Two concrete edits required:**

**Edit A — `build.zig`:** After line 699 (`gptoss_test_mod.addImport("model/gptoss_manager.zig", ...)`),
add:
```zig
gptoss_test_mod.addImport("mlx.zig/src/mlx.zig", shared_mlx_mod);
```

**Edit B — `src/test_models_gptoss.zig`:** Add at the top with existing imports:
```zig
const mlx = @import("mlx.zig/src/mlx.zig");
```

**Edit C — `src/test_models_gptoss.zig` line 58:** Replace the `undefined` stream:
```zig
// Before:
var transformer = try GPTOSSTransformer.init(allocator, config, undefined);

// After:
const stream = mlx.defaultGpuStreamNew();
defer mlx.streamFree(stream);
var transformer = try GPTOSSTransformer.init(allocator, config, stream);
```

**Why `configureExecutable` alone is not enough:** `configureExecutable` at `build.zig:705` adds
C include paths and library linkage — it does not register Zig module aliases. The `addImport` call
is what makes `@import("mlx.zig/src/mlx.zig")` resolve inside the module.
