<objective>
Fix the module aliasing collision errors in `build.zig` that prevent six test targets from
compiling under `zig build test`.

**Root cause:** Each test sub-module (gptoss_mod, mxfp4_mod, gptoss_loader_mod, moe_mod, etc.)
calls `b.createModule(.{.root_source_file = "src/mlx.zig/src/mlx.zig"})` inline, creating
a distinct module object per call. When two modules both get their own mlx instance and are
linked together into the same test binary, Zig detects that the same physical file is registered
under two different module objects and reports:
  `file exists in modules 'mlx.zig/src/mlx.zig' and 'moe.zig'`

**Secondary fix:** `src/test_models_gptoss.zig:255` references `BackendType.mlx` which was
removed in Phase 17 Plan 02. This latent error would surface once module collisions are fixed.

**Fix:**
1. Create one shared `shared_mlx_mod` module variable before all test sub-module definitions
2. Wire this single instance as the mlx dependency for every sub-module that imports mlx
3. Fix `test_models_gptoss.zig:255`: `BackendType.mlx` → `BackendType.llama_cpp`

Output: `zig build test` no longer fails with module collision errors on the six affected targets.
</objective>

**Collision pattern for gptoss_test:**
```
src/backends/mlx_gptoss_backend.zig:1:1: error: file exists in modules 'mlx.zig/src/mlx.zig' and '../backends/mlx_gptoss_backend.zig'
```
Caused by: `gptoss_mod` and `gptoss_loader_mod` each create their own mlx module instance inline.
When `mlx_gptoss_backend_mod` depends on BOTH, two different mlx objects point to the same file.

**Collision pattern for moe_test:**
```
src/moe.zig:1:1: error: file exists in modules 'mlx.zig/src/mlx.zig' and 'moe.zig'
```
Caused by: `moe_mod` is created without any mlx dependency wired, so `moe.zig`'s
`@import("mlx.zig/src/mlx.zig")` is unresolved. When combined with `moe_test_mod`'s own
mlx instance, Zig sees a conflict.

**Collision pattern for gptoss_manager_test:**
```
src/weight/gptoss_loader.zig:1:1: error: file exists in modules 'mlx.zig/src/mlx.zig' and '../weight/gptoss_loader.zig'
```
Same root cause — gptoss_loader_mod has its own mlx instance.

**Collision pattern for deepseek_test:**
```
src/mlx.zig/src/mla.zig:1:1: error: file exists in modules 'mlx.zig/src/mlx.zig' and 'mlx.zig/src/mla.zig'
```
Caused by: `mla.zig` imports `@import("mlx.zig")` (its parent's module), but `mla_mod` is
registered as a separate top-level module without that dependency wired.

**Fix pattern (shared module):**

gptoss_loader_mod.addImport("mlx.zig/src/mlx.zig", shared_mlx_mod);  // was inline b.createModule()
