2. **Performance Benchmarks:**
```bash
# Measure tokens per second
measure_performance() {
    local model=$1
    local start_time=$(date +%s.%N)
    
    # Generate 100 tokens
    curl -s -X POST http://localhost:$SERVER_PORT/v1/chat/completions \
      -H "Content-Type: application/json" \
      -d "{\"model\": \"$model\", \"messages\": [{\"role\": \"user\", \"content\": \"Count to 100\", \"max_tokens\": 100, \"stream\": false}"
    
    local end_time=$(date +%s.%N)
    local duration=$(echo "$end_time - $start_time" | bc)
    local tps=$(echo "scale=2; 100 / $duration" | bc)
    
    echo "$model: $tps tokens/sec"
}
```

3. **Memory Leak Detection:**
```bash
# Test for memory leaks over multiple requests
test_memory_leak() {
    local model=$1
    local initial_mem=$(get_memory_usage)
    
    # Run 10 generations
    for i in {1..10}; do
        curl -s -X POST ... # generate 50 tokens
    done
    
    local final_mem=$(get_memory_usage)
    local growth=$(echo "$final_mem - $initial_mem" | bc)
    
    if (( $(echo "$growth > 100" | bc -l) )); then
        echo "WARNING: Memory grew by ${growth}MB - possible leak"
        return 1
    fi
}
```

# Test various context lengths
test_context_lengths() {

        fi

}

### Task 3: Regression Detection (0.5h)

**Baseline Tracking:**
```bash
# Save performance baselines
save_baseline() {
    local model=$1
    local metric=$2
    local value=$3
    
    echo "$model,$metric,$value,$(date +%s)" >> .test_baselines.csv
}

# Check for regression
check_regression() {
    local model=$1
    local metric=$2
    local current_value=$3
    local threshold=${4:-0.8}  # 80% of baseline
    
    local baseline=$(grep "^$model,$metric," .test_baselines.csv | tail -1 | cut -d',' -f3)
    
    if (( $(echo "$current_value < $baseline * $threshold" | bc -l) )); then
        echo "REGRESSION: $model $metric dropped to $current_value (baseline: $baseline)"
        return 1
    fi
}
```

- Server must start reliably
- curl and python3 for test execution
- bc for floating-point math in bash
- CI/CD environment (GitHub Actions)

## Risks

| Risk | Mitigation |
|------|------------|
| CI machine doesn't have GPU | Use self-hosted runner with Mac mini |
| Model download times out | Cache models between runs |
| Concurrent tests conflict | Use different ports or sequential execution |
| False positives from network issues | Retry failed tests once |

## Notes

- Focus on detecting regressions, not absolute performance
- Use 1.5B model for quick CI tests, full suite for nightly
- Store baselines in repo, update manually when improving performance
- Don't block PRs on performance fluctuations, only major regressions
- Memory leak detection is more important than speed benchmarks
