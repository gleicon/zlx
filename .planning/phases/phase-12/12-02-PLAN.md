# Plan 12-02: GPT-OSS Architecture Support

## Goal
Add complete support for GPT-OSS-20B model with its unique MoE + sliding window attention architecture, enabling it to load and run inference on the zlx server.

## Background

**What is GPT-OSS?**
- OpenAI's open-source model (20B parameters)
- Mixture of Experts: 32 experts, 4 per token
- Sliding window attention: alternating attention patterns
- 128K context with Yarn rope scaling
- MXFP4 quantized (available from MLX community)

**Architecture Differences from DeepSeek:**

| Feature | DeepSeek V2 | GPT-OSS |
|---------|-------------|---------|
| Total Params | 15.7B | 20B |
| Experts | 64 | 32 |
| Experts per Token | 6 | 4 |
| Attention | MLA (compressed KV) | Sliding Window |
| Window Size | Full context | 128 tokens (every other layer) |
| RoPE | Standard | Yarn (32x scaling) |
| Activation | SwiGLU | SwiGLU with limit |
| Layers | 27 | 24 |

## Technical Details

### Sliding Window Attention

GPT-OSS uses alternating attention patterns:
- Layer 0, 2, 4, ... (even): Sliding window (128 tokens)
- Layer 1, 3, 5, ... (odd): Full attention

**Implementation:**
```zig
fn createAttentionMask(seq_len: usize, layer_idx: usize) !mlx.Array {
    if (layer_idx % 2 == 0) {
        // Sliding window: only attend to last 128 tokens
        return createSlidingWindowMask(seq_len, 128);
    } else {
        // Full attention: standard causal mask
        return createCausalMask(seq_len);
    }
}
```

### Yarn RoPE Scaling

GPT-OSS extends 4K base context to 128K via Yarn:
- `rope_theta`: 150,000 (vs 10,000 standard)
- `rope_scaling.factor`: 32.0
- `rope_scaling.beta_fast`: 32.0
- `rope_scaling.beta_slow`: 1.0

**Implementation:**
```zig
fn applyYarnRope(x: mlx.Array, position: usize, head_dim: usize) !mlx.Array {
    // Extended RoPE with frequency scaling
    // Scale frequencies based on position
}
```

### SwiGLU with Limit

GPT-OSS uses modified SwiGLU with output limiting:
```zig
fn swigluWithLimit(x: mlx.Array, limit: f32) !mlx.Array {
    var activated = mlx.arrayNew();
    defer mlx.arrayFree(activated);
    try mlx.swiglu(&activated, x, null);
    
    // Apply limit: clamp(activated, -limit, limit)
    return mlx.clamp(activated, -limit, limit);
}
```

## Memory Optimization

GPT-OSS-20B requires ~11GB in 4-bit quantization:
- Model weights: ~9GB
- KV cache (4K context): ~1.5GB
- Activations: ~0.5GB
- **Total: ~11GB**

On 16GB MacBook:
- Leave 5GB for OS/other apps
- Use TurboQuant to reduce KV cache by 4.6x
- Max context: ~16K with TurboQuant

## Error Handling

**Missing Weights:**
- GPT-OSS has some optional weights (bias terms)
- Check config for `attention_bias: true`
- Log and skip optional weights

**Shape Mismatches:**
- GPT-OSS uses head_dim=64 (vs DeepSeek variable)
- Verify: num_heads=64, hidden_size=2880, head_dim=45? No, 2880/64=45

Wait, let me recalculate:
- hidden_size: 2880
- num_attention_heads: 64
- head_dim: 64 (from config)
- So 64 heads × 64 dim = 4096... but hidden_size is 2880?

Actually, this suggests GQA (Grouped Query Attention):
- num_key_value_heads: 8 (from config)
- So Q: 64 heads, K/V: 8 heads (repeated)
- head_dim: 64 for all

**Verification:** Check for GQA pattern in weight shapes.
