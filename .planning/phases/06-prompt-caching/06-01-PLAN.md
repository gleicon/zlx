## Key Implementation Context

### Current KV Cache Structure (src/mlx.zig/src/mlx.zig:980-1065)
```zig
pub const KVCache = struct {
    k: Array,           // MLX array for keys
    v: Array,           // MLX array for values  
    axis: c_int,        // Concatenation axis (usually 2)
    is_empty: bool = true,
};

pub const Cache = struct {
    layers: []KVCache,  // One per transformer layer
    offset: c_int,      // Current position
    allocator: std.mem.Allocator,
};
```

### MLX Array Save/Load Pattern
MLX provides `mlx_save_safetensors` and `mlx_load_safetensors_file` for persisting arrays. The Cache contains arrays that can be serialized using safetensors format.

### Generation Flow (src/inference/generator.zig:106-189)
GenerationState creates a fresh Cache in `init()`:
```zig
const cache = try allocator.create(mlx.Cache);
cache.* = try mlx.Cache.init(allocator, transformer.model.layers.len, 2);
```

The prompt is processed first (full forward pass), then tokens are generated one at a time. For caching, we need to:
1. Save the cache state AFTER prompt processing, BEFORE generation starts
2. On cache hit, restore the saved cache and skip prompt processing

### Cache Key Requirements (from PERF-02)
Must include:
- Model hash (different models = different cache entries)
- Prompt hash (exact text match required)
- Sampling params (temperature, top_p, etc. affect logits → different KV states)

### Memory Considerations (from 05-03)
Current KV cache size formula: `2 × layers × hidden_size × seq_len × dtype_bytes`
For Qwen 7B: 2 × 28 × 3584 × 4096 × 2 bytes = ~1.6GB per 4K context
With prompt caching, we store this on disk, load on demand.
