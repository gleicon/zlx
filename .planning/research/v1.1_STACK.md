# Technology Stack: zlx v1.1 Features

**Project:** zlx — Zig LLM Inference Server v1.1  
**Domain:** OpenAI-compatible local LLM inference server with advanced features  
**Researched:** 2026-04-01  
**Confidence:** HIGH (verified against MLX ecosystem, OpenAI API spec, and local LLM server patterns)

---

## Executive Summary

zlx v1.1 introduces seven major feature categories that extend the minimal v1.0 foundation: TurboQuant KV-cache compression, multi-model support, prompt caching, Web UI, API improvements, performance optimizations, and model management. The technology stack remains Zig 0.13.0 + MLX.zig + httpz, with new components added strategically. Key insight: TurboQuant remains Python-only but viable paths forward exist via Metal kernel source extraction or mlx-c custom ops. Multi-model support and prompt caching can be implemented within existing MLX.zig patterns. Web UI should leverage external projects like Open WebUI rather than building custom.

## v1.1 Feature-Specific Technologies

### 1. TurboQuant KV-Cache Compression

**Status:** Requires implementation strategy decision — Python-only library confirmed, no C/C++ API exists.

| Approach | Effort | Viability | Notes |
|----------|--------|-----------|-------|
| **Extract Metal kernels from turboquant-mlx** | Medium | HIGH | TurboQuant kernels are embedded Python strings via `mx.fast.metal_kernel()`; extract MSL source and compile via `xcrun metal` — verified from repo inspection |
| Native Zig quantization via mlx-c primitives | High | MEDIUM | Reimplement Hadamard rotation + Lloyd-Max quantization; loses kernel fusion benefits |
| Upgrade mlx-c to v0.4.1 for custom ops API | High | LOW | Breaks MLX.zig compatibility; would require MLX.zig fork |
| Python sidecar (not recommended) | Very High | LOW | Defeats "no Python" constraint |

**Recommended Approach:** Extract Metal shader source strings from `turboquant_mlx/metal_kernels.py` and `metal_kernels_v2.py`, compile standalone `.metallib`, load via MLX-C array operations. The kernels use standard Metal compute patterns — the `mx.fast.metal_kernel()` calls are just JIT wrappers around raw MSL.

**Files to Extract:**
- `turboquant_mlx/metal_kernels.py` — v1 serial kernels (~100 LOC MSL)
- `turboquant_mlx/metal_kernels_v2.py` — v2 parallel WHT with threadgroup barriers (~150 LOC MSL)
- `turboquant_mlx/fused_attention.py` — fused Q@K^T without materialization

**Build Integration:** Add `b.addSystemCommand` steps in `build.zig`:
```bash
xcrun -sdk macosx metal turboquant.metal -o turboquant.air
xcrun -sdk macosx metallib turboquant.air -o turboquant.metallib
```

### 2. Multi-Model Support

**Components Required:**

| Component | Purpose | Implementation Approach |
|-----------|---------|-------------------------|
| Model Registry | Track available models | JSON file in `~/.zlx/models.json` or scan `./models/` directory |
| Hot-Unload/Reload | Switch without restart | MLX memory management allows this via `mlx_array_free()` on model weights; load new weights into same allocator |
| Model State Machine | Track loading/unloading | Enum: `unloaded` → `loading` → `ready` → `unloading` |
| Memory Budget Manager | Prevent OOM when switching | Query `mach_task_basic_info` for available memory; refuse load if model > 80% of free RAM |

**Key MLX Pattern:**
```zig
// Unload current model
for (model_weights) |weight| {
    mlx_array_free(weight.c_array);
}
// Force Metal garbage collection
mlx_synchronize(stream);
// Load new model
var new_model = try Transformer.init(allocator, new_model_path);
```

### 3. Prompt Caching (KV-Cache Persistence)

**Purpose:** Eliminate TTFT (Time To First Token) for repeated contexts by caching KV cache state.

| Aspect | Approach | Notes |
|--------|----------|-------|
| Cache Key | SHA-256 of tokenized prompt | Store as filename or lookup key |
| Cache Storage | `~/.zlx/cache/<model_hash>/<prompt_hash>.cache` | Binary dump of MLX arrays via `mlx_save()` |
| Cache Lifetime | LRU with max size | Configurable via `--cache-size-mb` |
| Cache Format | MLX native `.safetensors` or `.npy` | MLX-C has `mlx_save`/`mlx_load` for arrays |

**OpenAI API Mapping:**
- Request: `POST /v1/chat/completions` with `cache_key: "my-cache-key"` (extension to standard API)
- Alternative: Use `prompt_cache` parameter as in vLLM/TensorRT-LLM

**Key MLX APIs:**
```c
// Save cache
mlx_save(cache_file_path, k_cache_array);
mlx_save(cache_file_path_v, v_cache_array);

// Load cache  
mlx_array k_cache = mlx_load(cache_file_path);
```

### 4. Web UI

**Recommendation: Do NOT build custom. Integrate with existing solutions.**

| Option | Rationale | Integration |
|--------|-----------|-------------|
| **Open WebUI** (recommended) | 46K+ stars, OpenAI-compatible, feature-rich, actively maintained | zlx server is already OpenAI-compatible; just point Open WebUI at `http://localhost:8080/v1` |
| Text Generation WebUI | 46K+ stars, but heavier Python dependency | Works but adds Python runtime |
| Custom Zig/WASM UI | High effort, low differentiation | Not recommended for MVP |

**Open WebUI Integration Steps:**
1. User installs Open WebUI: `docker run -d -p 3000:8080 -e OPENAI_API_BASE_URL=http://host.docker.internal:8080/v1 ghcr.io/open-webui/open-webui:main`
2. Configure Open WebUI to use zlx as backend
3. All chat, model switching, history managed by Open WebUI
4. zlx focuses on inference only

**Why This Approach:**
- Open WebUI has 46K GitHub stars — battle-tested UI
- No frontend build pipeline needed in zlx
- Keeps zlx as pure inference server (Unix philosophy)
- Users who want UI get best-in-class experience

### 5. API Improvements

**Missing OpenAI API Features to Add:**

| Feature | OpenAI Spec | Implementation in zlx | Complexity |
|---------|-------------|----------------------| ------------|
| `stop` sequences | Array of strings or single string | Tokenize stop strings, check after each generation step | LOW |
| `logprobs` | Integer 1-10 | Track top-k logits during sampling, return in `choices[].logprobs` | MEDIUM |
| `logit_bias` | Map token_id → bias | Add bias to logits before softmax | LOW |
| `top_k` | Integer | Sampling parameter — already in MLX.zig | LOW |
| `min_p` | Float 0.0-1.0 | Minimum probability threshold — already in MLX.zig | LOW |
| `presence_penalty` | Float | Penalize tokens already appeared | LOW |
| `frequency_penalty` | Float | Penalize tokens proportional to count | LOW |
| `n` (multiple completions) | Integer | Generate N sequences (inference cost increases) | MEDIUM |
| `response_format` | JSON Schema | Constrained decoding — requires grammar parser | HIGH |

**Implementation Priority:**
1. HIGH: `stop`, `logprobs`, `logit_bias`, `top_k`, `min_p` — all supported by MLX.zig
2. MEDIUM: `presence_penalty`, `frequency_penalty`, `n` — adds sampling logic
3. LOW: `response_format` — requires JSON schema parser + constrained decoding

### 6. Performance Optimizations

| Technique | Viability for zlx | Implementation Approach | Expected Gain |
|-----------|-------------------|------------------------|---------------|
| **Continuous Batching** | LOW | Requires async request queue + dynamic batch formation; MLX is single-stream | Not recommended |
| **Speculative Decoding** | MEDIUM | Load draft model (smaller), generate N draft tokens, verify with target model | 1.5-2.8x speedup per vLLM benchmarks |
| **Quantization Improvements** | HIGH | Use MLX-community pre-quantized 4-bit models (already supported) | 2-4x memory reduction |
| **Flash Attention** | HIGH | MLX uses Metal Performance Shaders; already optimized | Built-in |
| **PagedAttention** | LOW | vLLM technique; MLX memory model is different (unified memory) | Not applicable |

**Speculative Decoding Implementation:**
```zig
// Load draft model (e.g., Qwen2.5-1.5B for Qwen2.5-7B target)
var draft_model = try Transformer.init(allocator, "draft-model");

// Generate loop
while (!finished) {
    // Draft model generates N tokens
    const draft_tokens = try draft_model.generate_draft(current_context, num_draft_tokens);
    
    // Target model verifies all draft tokens in parallel
    const verified_count = try target_model.verify_draft(draft_tokens);
    
    // Accept verified tokens, reject rest
    accepted_tokens += verified_count;
}
```

### 7. Model Management

**Features:**

| Feature | Implementation | Notes |
|---------|---------------|-------|
| **HuggingFace Integration** | `GET /v1/models` queries HF Hub via `huggingface_hub` library equivalent | Requires HTTP client + token auth |
| **Model Auto-Download** | Download from `mlx-community/` org on HF | Use `std.http.Client` for chunked download |
| **Model Organization** | `~/.zlx/models/<org>/<model>/` directory structure | Mirror HuggingFace cache structure |
| **Model Verification** | SHA-256 checksum verification after download | HF provides `sha` in model card |

**HTTP Download Implementation (Zig stdlib):**
```zig
const client = std.http.Client{ .allocator = allocator };
const uri = std.Uri.parse("https://huggingface.co/.../model.safetensors") catch unreachable;

var headers = std.http.Headers{ .allocator = allocator };
try headers.append("Authorization", "Bearer hf_xxx");

var req = try client.request(.GET, uri, headers, .{});
try req.start();
try req.wait();

// Stream to file
const file = try std.fs.cwd().createFile("model.safetensors", .{});
defer file.close();

var buffer: [8192]u8 = undefined;
while (true) {
    const bytes_read = try req.read(&buffer);
    if (bytes_read == 0) break;
    try file.writeAll(buffer[0..bytes_read]);
}
```

## Alternatives Considered

| Feature | Recommended | Alternative | Why Not Alternative |
|---------|-------------|-------------|---------------------|
| TurboQuant | Extract Metal kernels, compile standalone | Native Zig reimplementation | Kernel fusion benefits lost; complex quantization math |
| Multi-Model | Hot-swap via MLX memory management | Multi-process architecture | Adds IPC complexity; MLX unified memory favors single process |
| Prompt Caching | MLX native `mlx_save`/`mlx_load` | Custom binary format | Use MLX primitives for compatibility |
| Web UI | Integrate Open WebUI | Build custom | High effort, low differentiation |
| Model Download | `std.http.Client` | libcurl binding | Zig stdlib sufficient; avoid C dep |

---

## What NOT to Use

| Avoid | Why | Use Instead |
|-------|-----|-------------|
| TurboQuant Python runtime | Defeats "no Python" constraint | Extract and compile Metal kernels standalone |
| Custom KV cache file format | Incompatible with MLX ecosystem | MLX native `mlx_save`/`mlx_load` |
| React/Vue frontend in zlx | Adds 100MB+ node_modules, build complexity | External Open WebUI integration |
| libcurl for HTTP download | Unnecessary C dependency | `std.http.Client` |
| Continuous batching | MLX is single-stream GPU; adds complexity without gain | Sequential with mutex |
| PagedAttention | vLLM optimization; MLX uses unified memory | MLX native memory management |
