# Pitfalls: zlx v1.1 Features

**Project:** zlx — Zig LLM Inference Server v1.1  
**Domain:** Advanced features pitfalls (multi-model, prompt caching, TurboQuant, performance optimizations)  
**Researched:** 2026-04-01  
**Confidence:** HIGH (derived from existing research, MLX ecosystem patterns, local LLM server post-mortems)

---

## Critical Pitfalls

### Pitfall 1: TurboQuant Metal Kernel Extraction Is Non-Trivial

**What goes wrong:** The TurboQuant Metal kernels are embedded as Python strings in `turboquant_mlx/metal_kernels_v2.py`. Extracting and compiling them standalone requires understanding MLX's `mx.fast.metal_kernel()` internals, threadgroup barrier patterns, and buffer binding conventions. Naive extraction will produce Metal shaders that crash or produce wrong results.

**Why it happens:** The MSL source is intertwined with Python JIT compilation logic. The kernels use:
- Dynamic buffer binding (MLX-specific convention)
- Threadgroup barriers for parallel Walsh-Hadamard Transform
- Custom quantization codebook lookup tables

**Consequences:**
- Metal runtime crashes (`MTLCommandBufferErrorFailure`)
- Silent wrong outputs (quantization errors compound)
- Performance worse than baseline FP16

**Prevention:**
1. Carefully extract MSL strings from Python files (lines 40-200 in `metal_kernels_v2.py`)
2. Study MLX's Metal kernel binding API in `mlx/c/metal.h`
3. Write unit tests for individual kernels before integration:
   - Test Hadamard rotation: input → rotation → should match Python reference
   - Test quantization: random Gaussian → quantize → dequantize → check SNR
   - Test fused attention: small known input → verify output

**Detection:**
- Unit test failures for quantization round-trip
- `metallib` loads but produces NaN outputs
- TurboQuant-enabled model generates gibberish

**Phase to address:** Research phase before TurboQuant implementation — verify kernel extraction and compilation work independently.

### Pitfall 2: Model Switching Without Proper MLX Cleanup

**What goes wrong:** When switching models, MLX arrays from the previous model remain in Metal memory. Loading a second model without proper cleanup causes OOM or silent memory corruption.

**Why it happens:** MLX uses reference counting, but arrays can be retained by:
- Autorelease pools
- Stream command buffers still in flight
- Accidental references in Zig code (e.g., stored in old structs)

**Consequences:**
- Out-of-memory crash on second model load
- Silent corruption of new model weights
- Performance degradation ( Metal paging)

**Prevention:**
```zig
pub fn unloadModel(self: *ModelManager) void {
    // 1. Ensure no generation in progress
    if (self.generation_state == .generating) {
        self.cancelGeneration();
    }
    
    // 2. Free all MLX arrays
    for (self.current_model.weights) |weight| {
        mlx_array_free(weight.c_array);
    }
    
    // 3. Free cache
    if (self.current_model.cache) |*cache| {
        cache.deinit();
    }
    
    // 4. Synchronize Metal stream
    mlx_synchronize(self.stream);
    
    // 5. Null out all references
    self.current_model = null;
    
    // 6. Optional: force MLX garbage collection
    // (MLX may not expose this directly, but synchronize should help)
}
```

**Detection:**
- Memory usage (RSS) doesn't drop after unload
- Second model load fails with OOM
- Activity Monitor shows growing "Memory Used"

**Phase to address:** Phase 2 (Model Manager) — establish unload discipline before implementing switch.

### Pitfall 3: KV Cache Persistence Format Incompatibility

**What goes wrong:** Saved KV cache from one version of zlx fails to load in another version, or cache from one model loads into another producing garbage.

**Why it happens:**
- MLX array format changes between versions
- Model architecture changes (layer count, head_dim)
- Different quantization schemes

**Consequences:**
- Crash on cache load (`mlx_load` returns null or corrupt array)
- Silent quality degradation (wrong KV values produce gibberish)
- Cache "poisoning" — saved bad cache and used repeatedly

**Prevention:**
1. Include version metadata in cache files:
```zig
const CacheHeader = struct {
    magic: [4]u8 = "ZKCH",  // zlx cache
    version: u32 = 1,
    model_hash: [32]u8,      // SHA-256 of model weights
    mlx_version: [16]u8,    // MLX library version
    layer_count: u32,
    head_dim: u32,
    sequence_length: u32,
};
```

2. Validate on load:
```zig
pub fn loadCache(path: []const u8, expected_model_hash: [32]u8) !KVCache {
    const header = try readHeader(path);
    
    if (!std.mem.eql(u8, &header.magic, "ZKCH")) {
        return error.InvalidCacheFormat;
    }
    
    if (!std.mem.eql(u8, &header.model_hash, &expected_model_hash)) {
        return error.WrongModel;  // Critical: don't load cache from different model
    }
    
    if (header.version != CURRENT_CACHE_VERSION) {
        return error.CacheVersionMismatch;
    }
    
    // ... proceed to load
}
```

3. Auto-evict incompatible caches on startup

**Detection:**
- Cache load produces arrays with wrong shapes
- Generation quality drops suddenly after cache load
- `mlx_load` returns errors

**Phase to address:** Phase 3 (Prompt Caching) — design cache format with validation from day one.

### Pitfall 4: Unbounded Prompt Cache Growth

**What goes wrong:** Every unique prompt generates a cache entry. Over time, disk fills with cache files. No eviction policy means permanent growth.

**Why it happens:**
- Each chat session has unique context
- Developer testing generates many ephemeral caches
- No TTL or LRU eviction

**Consequences:**
- Disk full on user machine
- Cache lookup slows down (linear scan of many files)
- Cache directory corruption risk

**Prevention:**
```zig
const CacheManager = struct {
    max_size_bytes: usize = 10 * 1024 * 1024 * 1024,  // 10GB default
    max_entries: usize = 1000,
    
    pub fn save(self: *CacheManager, key: []const u8, cache: KVCache) !void {
        const size = cache.estimateSize();
        
        // Evict until we have room
        while (self.current_size + size > self.max_size_bytes or 
               self.entries.count() >= self.max_entries) {
            const oldest = self.lru_queue.popFirst();
            try self.evict(oldest.key);
        }
        
        // Save new cache
        try self.doSave(key, cache);
        self.current_size += size;
        
        // Add to LRU
        self.lru_queue.append(key);
        
        // Persist metadata
        try self.saveMetadata();
    }
    
    pub fn load(self: *CacheManager, key: []const u8) !?KVCache {
        const entry = self.entries.get(key) orelse return null;
        
        // Update LRU on access
        self.lru_queue.moveToBack(entry.node);
        
        return try self.doLoad(key);
    }
};
```

**Detection:**
- `~/.zlx/cache/` directory growing monotonically
- Cache operations taking longer over time
- Disk space warnings

**Phase to address:** Phase 3 — implement eviction from first release.

### Pitfall 5: Speculative Decoding Draft/Model Mismatch

**What goes wrong:** Draft model generates tokens that are completely wrong for the target model, causing 100% rejection rate. Result: slower than baseline (overhead of draft generation with zero accepted tokens).

**Why it happens:**
- Draft model from different family (e.g., Llama draft for Qwen target)
- Tokenizer mismatch (different vocabularies)
- Context window mismatch (draft handles shorter context)

**Consequences:**
- Slower than without speculative decoding
- Wasted GPU memory for draft model
- User confusion ("why is it slower?")

**Prevention:**
1. Only pair compatible models:
   | Target | Valid Drafts |
   |--------|--------------|
   | Qwen2.5-* | Qwen2.5-1.5B, Qwen2.5-3B |
   | Llama-3.* | Llama-3.2-1B, Llama-3.2-3B |
   | Phi-4 | Phi-3-mini, Phi-3-small |

2. Validate tokenizer vocab size match before enabling:
```zig
pub fn canSpeculate(target: *Model, draft: *Model) bool {
    return target.tokenizer.vocab_size == draft.tokenizer.vocab_size;
}
```

3. Start with conservative `num_draft_tokens=2`, increase if acceptance rate >50%

**Detection:**
- Acceptance rate near 0% (log metrics)
- Speculative path slower than baseline in benchmarks
- Token streams show mismatched token IDs

**Phase to address:** Phase 4 (Speculative Decoding) — add compatibility check before enabling.

### Pitfall 6: Sampling Parameter Conflicts

**What goes wrong:** Multiple sampling parameters interact in unexpected ways, producing degenerate outputs (all same token, random gibberish, or no output).

**Why it happens:**
- `temperature=0` (greedy) + `top_k=1` + `min_p=0.5` = no valid tokens
- `presence_penalty` set too high drives probability to 0 for all tokens
- `logit_bias` pushes all logits negative, softmax produces NaN

**Consequences:**
- Generation hangs (no token meets criteria)
- Endless repetition of single token
- Crash in softmax (division by zero)

**Prevention:**
```zig
pub fn validateSamplingConfig(config: SamplingConfig) !void {
    // Temperature must be >= 0
    if (config.temperature < 0) return error.InvalidTemperature;
    
    // If temperature is 0 (greedy), other constraints must be relaxed
    if (config.temperature == 0) {
        if (config.min_p > 0) {
            std.log.warn("min_p disabled with temperature=0");
            config.min_p = 0;
        }
    }
    
    // Penalties shouldn't exceed reasonable bounds
    if (config.presence_penalty > 2.0) {
        std.log.warn("Clamping presence_penalty to 2.0");
        config.presence_penalty = 2.0;
    }
    
    // Ensure at least one token is selectable
    if (config.top_k == 1 and config.min_p > 0.99) {
        return error.ImpossibleConstraints;
    }
}

pub fn applySampling(logits: mlx.Array, config: SamplingConfig) !u32 {
    var modified = logits;
    
    // Apply temperature
    if (config.temperature > 0) {
        modified = mlx.multiply(logits, 1.0 / config.temperature);
    }
    
    // Top-k
    if (config.top_k > 0) {
        modified = mlx.topk_mask(modified, config.top_k);
    }
    
    // Top-p (nucleus)
    if (config.top_p < 1.0) {
        modified = mlx.toppsort(modified, config.top_p);
    }
    
    // Min-p
    if (config.min_p > 0) {
        const max_logit = mlx.max(modified);
        const min_logit = max_logit + @log(config.min_p);  // log(p_min)
        modified = mlx.where(mlx.greater(modified, min_logit), modified, -inf);
    }
    
    // Check if any valid tokens remain
    if (mlx.all(mlx.equal(modified, -inf))) {
        return error.NoValidTokens;
    }
    
    // Sample
    return mlx.argmax(mlx.softmax(modified));
}
```

**Detection:**
- Generation stops with "NoValidTokens" error
- All output tokens are the same
- Benchmark outputs are garbage

**Phase to address:** Phase 1 (API validation) — validate configs; Phase 2 (Sampling pipeline) — add safeguards.

### Pitfall 7: Memory Budget Miscalculation

**What goes wrong:** Model manager allows loading a model that exceeds available RAM + VRAM, causing OOM crash or severe swapping.

**Why it happens:**
- Model size calculated from file size (doesn't include KV cache overhead)
- Metal unified memory accounting is complex
- Other processes consuming memory

**Consequences:**
- macOS kernel kills zlx (OOM)
- System becomes unresponsive (swap thrashing)
- Corrupted Metal driver state (requires reboot)

**Prevention:**
```zig
pub fn checkMemoryBudget(model_path: []const u8) !bool {
    // 1. Get model file size
    const model_size = try std.fs.cwd().statFile(model_path).size;
    
    // 2. Estimate runtime overhead (KV cache, activations, temporaries)
    const overhead_ratio = 1.5;  // 50% overhead for safety
    const estimated_needed = @as(f64, @floatFromInt(model_size)) * overhead_ratio;
    
    // 3. Query available memory
    const available = try queryAvailableMemory();  // mach_task_basic_info
    
    // 4. Require 20% headroom for OS and other apps
    const usable = available * 0.8;
    
    if (estimated_needed > usable) {
        std.log.err("Model requires {d:.1}GB but only {d:.1}GB available", 
            .{ estimated_needed / 1e9, usable / 1e9 });
        return false;
    }
    
    return true;
}

// Query actual available memory on macOS
pub fn queryAvailableMemory() !usize {
    var info: std.c.mach_task_basic_info = undefined;
    var count = std.c.mach_task_basic_info_count;
    
    const kr = std.c.task_info(
        std.c.mach_task_self(),
        std.c.mach_task_basic_info,
        @ptrCast(&info),
        &count
    );
    
    if (kr != 0) return error.MachError;
    
    // Available = free + inactive + speculative - wired
    return info.phys_footprint;
}
```

**Detection:**
- OOM crashes during model load
- Activity Monitor shows memory pressure in red
- Console shows `EXC_RESOURCE` (CPU/IO resource exceeded)

**Phase to address:** Phase 2 (Model Manager) — implement budget check before any load.

### Pitfall 8: HTTP Download Blocking Inference

**What goes wrong:** Model download happens on the main thread, blocking all inference requests for minutes.

**Why it happens:**
- Download implemented synchronously in request handler
- Large models (4-8GB) take 5-15 minutes to download
- No progress indication to client

**Consequences:**
- Server appears frozen during download
- Client timeouts (504 Gateway Timeout)
- Cannot interrupt download

**Prevention:**
```zig
// Background download thread
var download_thread: ?std.Thread = null;
var download_queue: DownloadQueue = .{};

pub fn handleDownloadRequest(req: Request, res: Response) !void {
    // Queue the download, don't do it here
    const task = DownloadTask{
        .repo_id = req.repo_id,
        .on_progress = updateProgress,
        .on_complete = |result| {
            if (result) |_| {
                model_manager.registerDownloadedModel(task.repo_id);
            } else |e| {
                std.log.err("Download failed: {}", .{e});
            }
        },
    };
    
    try download_queue.push(task);
    
    // Return immediately with "queued" status
    try res.json(.{
        .status = "queued",
        .repo_id = req.repo_id,
        .queue_position = download_queue.len(),
    });
}

// Download worker thread
fn downloadWorker() void {
    while (true) {
        const task = download_queue.pop() orelse break;
        downloadWithProgress(task) catch |e| {
            task.onComplete(e);
        };
        task.onComplete({});
    }
}

// Check status endpoint
pub fn handleDownloadStatus(req: Request, res: Response) !void {
    const status = download_manager.getStatus(req.repo_id);
    try res.json(status);
}
```

**Detection:**
- Server unresponsive during download
- Other requests timeout
- Long-running request in logs

**Phase to address:** Phase 3 (Download Manager) — always use background thread.

### Pitfall 9: Cache Key Collisions

**What goes wrong:** Different prompts produce the same cache key, causing KV cache reuse when it shouldn't happen. Results in wrong context being used.

**Why it happens:**
- Simple hash of prompt text (no model info)
- SHA-256 of tokenized prompt without model hash
- Collision in hash function (rare but possible)

**Consequences:**
- Silent wrong context usage
- Responses based on wrong cached KV
- Difficult to debug (appears as "model confusion")

**Prevention:**
```zig
pub fn generateCacheKey(model_hash: [32]u8, messages: []const Message) [64]u8 {
    var hasher = std.crypto.hash.sha2.Sha256.init(.{});
    
    // Include model hash (critical!)
    hasher.update(&model_hash);
    
    // Include tokenizer version if available
    hasher.update(tokenizer.version);
    
    // Include all message content
    for (messages) |msg| {
        hasher.update(msg.role);
        hasher.update(msg.content);
    }
    
    var result: [64]u8 = undefined;
    hasher.final(result[0..32]);
    
    // Encode as hex for filesystem safety
    _ = std.fmt.bufPrint(&result, "{s}", .{std.fmt.fmtSliceHexLower(result[0..32])}) catch unreachable;
    
    return result;
}
```

**Detection:**
- Cache hit for completely different prompts
- Model outputs reference wrong context
- Hash collision logged

**Phase to address:** Phase 3 — include model hash in all cache keys.

## Moderate Pitfalls

### Pitfall 10: CORS Issues with Open WebUI

**What goes wrong:** Open WebUI (running on port 3000) makes requests to zlx (port 8080). Browser blocks due to CORS policy.

**Why it happens:** Browsers enforce same-origin policy. Cross-origin requests require explicit CORS headers.

**Consequences:**
- Open WebUI can't connect to zlx
- Console shows CORS errors
- User thinks zlx is broken

**Prevention:**
```zig
pub fn handleChatCompletion(req: Request, res: Response) !void {
    // Add CORS headers
    try res.header("Access-Control-Allow-Origin", "*");
    try res.header("Access-Control-Allow-Methods", "POST, GET, OPTIONS");
    try res.header("Access-Control-Allow-Headers", "Content-Type, Authorization");
    
    // Handle preflight OPTIONS request
    if (req.method == .OPTIONS) {
        res.status = 204;
        return;
    }
    
    // ... rest of handler
}
```

**Phase to address:** Phase 1 (Server) — add CORS to all endpoints.

### Pitfall 11: Penalty Context Window Too Large

**What goes wrong:** Presence/frequency penalties applied to entire context window (32k tokens). Penalties accumulate to infinity, driving all logits to -inf.

**Why it happens:**
- Penalty calculation iterates all tokens in context
- No decay or windowing
- Common tokens ("the", "a") appear thousands of times

**Consequences:**
- No valid tokens (all probabilities 0)
- Generation hangs or crashes

**Prevention:**
```zig
pub fn applyPenalties(logits: mlx.Array, context: []const u32, config: SamplingConfig) mlx.Array {
    // Only look at recent context (configurable, default 1024)
    const window_size = @min(context.len, config.penalty_context_size);
    const recent_context = context[context.len - window_size ..];
    
    var modified = logits;
    
    // Count frequencies in window only
    var counts = std.AutoHashMap(u32, u32).init(allocator);
    defer counts.deinit();
    
    for (recent_context) |token_id| {
        const entry = counts.getOrPut(token_id) catch return logits;
        if (entry.found_existing) {
            entry.value_ptr.* += 1;
        } else {
            entry.value_ptr.* = 1;
        }
    }
    
    // Apply penalties
    var it = counts.iterator();
    while (it.next()) |entry| {
        const token_id = entry.key_ptr.*;
        const count = entry.value_ptr.*;
        
        const bias = config.presence_penalty + config.frequency_penalty * @as(f32, @floatFromInt(count));
        modified[token_id] -= bias;
    }
    
    return modified;
}
```

**Phase to address:** Phase 2 (Sampling) — always use limited context window for penalties.

### Pitfall 12: Logprobs Performance Overhead

**What goes wrong:** Computing logprobs for top-10 tokens at every step adds 10-20% overhead. Users who don't need logprobs pay the cost.

**Why it happens:**
- Logprobs require sorting entire vocabulary (30k-100k tokens) to find top-k
- Additional array allocations per token
- Logprobs computed even when client doesn't request them

**Consequences:**
- Slower generation for all users
- Increased memory allocations
- Unnecessary CPU/GPU sync

**Prevention:**
```zig
pub fn generateStep(self: *GenerationState, config: GenerationConfig) !StepResult {
    // ... forward pass ...
    
    var logprobs: ?Logprobs = null;
    if (config.logprobs) |n| {
        // Only compute if requested
        logprobs = try computeLogprobs(logits, n);
    }
    
    // Sample without full sort if no logprobs needed
    const next_token = if (logprobs) |lp|
        lp.tokens[0]  // Already computed
    else
        try fastSample(logits, config.sampling);
    
    return StepResult{
        .token = next_token,
        .logprobs = logprobs,
    };
}
```

**Phase to address:** Phase 2 — conditional logprobs computation.

## "Looks Done But Isn't" Checklist v1.1

- [ ] **TurboQuant:** Compiles and runs — verify against FP16 baseline for correctness (perplexity), not just speed
- [ ] **Multi-Model:** Can switch models — verify memory drops between switches (Activity Monitor)
- [ ] **Prompt Caching:** Cache saves and loads — verify TTFT is <1s on second request for same prompt
- [ ] **Cache Eviction:** Fill cache to limit — verify oldest entries are removed automatically
- [ ] **Model Memory Budget:** Try load model larger than RAM — verify graceful error, not crash
- [ ] **Speculative Decoding:** Enable with compatible draft model — measure acceptance rate >30%
- [ ] **Download:** Start download via API — verify inference still works (other requests succeed)
- [ ] **CORS:** Test with Open WebUI — verify browser console shows no CORS errors
- [ ] **Sampling Penalties:** Set presence_penalty=2.0, frequency_penalty=2.0 — verify doesn't hang
- [ ] **Logprobs:** Request with logprobs: 10 — verify response includes logprob data without 20% slowdown on subsequent requests without logprobs
